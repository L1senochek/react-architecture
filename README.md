# Домашнее задание: Архитектура React-приложений

**(максимум — 12 баллов)**

## Цель

Закрепить принципы архитектурного проектирования React-приложений на основе
Feature-Sliced Design (FSD), научиться разделять ответственность между слоями и
применять FSD в практическом мини-проекте.

## Основная часть (до 10 баллов)

### 1. Создание проекта по FSD (3 балла)

#### Задание

Создайте новый проект на React с TypeScript и настройте базовую архитектуру по
принципам Feature-Sliced Design (FSD).

#### Что нужно сделать

a. Инициализируйте проект через Vite (npm create vite@latest).
b. Настройте такую структуру каталогов внутри src/:

```
src/
  app/
  entities/
  features/
  shared/
  pages/
  widgets/
```

Что должно находиться в app/:

- App.tsx — базовый корневой компонент.
- router.tsx — файл с определением маршрутов.

c. Настройте ESLint и Prettier с конфигурацией, отражающей принципы FSD:
поддержка абсолютных импортов через tsconfig paths. Рекомендуется
подключить алиасы сразу, чтобы избежать хаоса с относительными путями на
следующих этапах. Пример tsconfig.json с путями:

```
{
 "compilerOptions": {
   "baseUrl": "src",
   "paths": {
     "shared/*": ["shared/*"],
     "entities/*": ["entities/*"],
     "features/*": ["features/*"],
     "widgets/*": ["widgets/*"],
     "pages/*": ["pages/*"],
     "app/*": ["app/*"]
   }
 }
}
```

#### Критерии:

- Проект запускается без ошибок — 1 балл.
- Структура соответствует FSD — 1 балл.
- Настроены ESLint и Prettier с конфигурацией, отражающей принципы
  FSD, — 1 балл.

### 2. Реализация сущности Task (3 балла)

#### Задание

Создайте бизнес-сущность task в слое entities/. Опишите тип, реализуйте
UI-компонент для отображения задачи и примените стилизацию через CSS-модули.

#### Интерфейс задачи:

```
// entities/task/model/types.ts
export interface Task {
 id: string;
```

#### Компонент отображения:

Создайте компонент TaskCard.tsx — он должен быть презентационным, то есть:

- принимает данные через props;
- не содержит логики или side-effects;
- рендерит заголовок и статус (например, галочка/иконка/цвет);
- использует CSS-модули для стилизации.

#### Рекомендуемая структура папок:

```
entities/
task/
model/
types.ts
ui/
TaskCard.tsx
TaskCard.module.css
Стили для TaskCard должны располагаться рядом с компонентом, в файле
TaskCard.module.css.
```

#### Критерии:

- Типизация и структура — 1 балл.
- Компонент TaskCard с правильной презентационной логикой — 1 балл.
- Стили через .module.css — 1 балл.

### 3. Создание виджета «Список задач» (3 балла)

#### Задание

Реализуйте фичу taskList в слое widgets/. Она должна отображать список задач и
обеспечивать интерактивные действия: фильтрацию по статусу и удаление.

#### Рекомендуемая структура папок

```
widgets/
taskList/
model/
      useTasks.ts
    ui/
      TaskList.tsx
```

Используйте кастомный хук useTasks. API хука:

```
// widgets/taskList/model/useTasks.ts
import { Task } from 'entities/task/model/types';

export type Filter = 'all' | 'completed' | 'incomplete';

function useTasks(initial: Task[]): {
 tasks: Task[];                   // отфильтрованные задачи
 filter: Filter;                  // текущий фильтр
 setFilter: (f: Filter) => void;  // смена фильтра
 removeTask: (id: string) => void; // удаление задачи по ID
}
```

В качестве «начальных данных» для этого задания можно использовать локальный
массив прямо внутри хука (например, useState([...])).

#### Требования к логике:

- Задачи фильтруются по статусу:
  - "all" — все задачи;
  - "completed" — только завершенные;
  - "incomplete" — только незавершенные.

- При удалении задачи она исчезает из UI без перезагрузки.
- Все действия должны отражаться сразу в интерфейсе.

#### Критерии:

- Хук корректно реализует фильтрацию и удаление — 1 балл.
- Компонент TaskList правильно отображает отфильтрованные задачи — 1
  балл.
- Используется state-хук и проброс пропсов — 1 балл.

### 2. Мемоизация списка задач с useMemo (3 балла)

#### Задание

В хук `useTasks` добавьте `useMemo` для мемоизации отфильтрованного массива задач. В качестве «начальных данных» для этого задания используется локальный массив, передаваемый в хук `useTasks`.

#### Требования

- Фильтрация по статусу (`all`, `completed`, `incomplete`) выполняется через `useMemo`.
- Изменение фильтра или списка задач должно корректно отражаться в UI.

#### Граничные случаи

Обязательно протестируйте:

- Поведение при удалении задачи или изменении её статуса — `useMemo` не должен «запоминать» устаревшие данные.
- Сценарии, когда список задач пустой или содержит одну задачу.

#### Критерии

- `useMemo` применяется для фильтрации — 1 балл.
- UI обновляется корректно — 1 балл.
- Поведение не ломается — 1 балл.

### 3. Мемоизация функций с useCallback (3 балла)

#### Задание

В хуке `useTasks` оберните функцию `removeTask` в `useCallback`, чтобы ссылка на неё оставалась стабильной между рендерами. Мемоизация `removeTask` позволяет избежать лишних перерисовок `TaskCard`, если они обернуты в `React.memo`.
Без useCallback функция будет создаваться заново на каждый рендер, и React.memo не сможет «поймать» ее, как в прошлой версии.

#### Требования

- Мемоизированные функции передаются в `props` компонентов.
- Функции не создаются заново при каждом рендере.

#### Критерии

- Используется `useCallback` — 1 балл.
- Функции корректно передаются — 1 балл.
- Поведение не ломается — 1 балл.
